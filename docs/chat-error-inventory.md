# Web chat error inventory

Scope: product-owned errors in Web AI chat, document chat, shared chat, chat uploads, saved answers, rename/delete/restore and public share entry. The shared local execution card also appears in settings; its error text is localized there too. Mobile is outside this change. User messages, AI answers, reasoning, resource content, tool arguments and raw terminal stdout/stderr are not rewritten.

Audited on 2026-10-30 against Web baseline `840e6945af06c7cbe57261b0e842c4b954da5d37` and read-only Backend / Backend Pro source from GitHub. English server resources below are source evidence, not proof that every failure was reproduced in a running Web environment.

## Display policy

Keep scalar message/code/status as diagnostic inputs. Resolve known business codes first, then typed timeouts and exact legacy aliases. Unknown codes continue to HTTP fallback. Generic upstream aliases (`Unknown error`, `Failed to fetch from wizard`, `Inappropriate content`) do not override a more informative HTTP status. Render translations using the current UI language, independently of the AI output language. Unknown text, HTML, arrays and malformed messages use a local fallback. Never display an arbitrary upstream message as product error copy.

`Inappropriate content` is ambiguous: Wizard Pro pins `wizard-common@ea0cc4a7b32108825b420684e2545149832e2018`, where `wizard/utils.py` maps all `openai.APIError` to this message. It does not prove a content-policy violation. Connection loss, unreadable responses, timeouts and generic service failures do not prove that a write failed. The copy asks the user to check results before retrying; this change does not automatically replay a tool action.
